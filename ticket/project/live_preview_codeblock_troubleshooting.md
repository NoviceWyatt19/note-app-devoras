# Live Preview 코드 블록 트러블슈팅 정리

본 문서는 CodeMirror 6 기반의 WYSIWYG (Live Preview) 에디터에서 코드 블록(Code Block) 위젯을 구현할 때 발생한 주요 이슈 3가지와 그 근본 원인, 해결 방법을 기록합니다.

## 1. 방향키 접근 불가 및 라인 스킵 (Line Skip) 현상

### 증상
위/아래 방향키를 사용하여 코드를 탐색할 때, 에디터 커서가 코드 블록 상단의 타이틀 바 위젯이나 하단의 닫는 펜스(` ``` `) 라인에 멈추지 않고 통째로 건너뛰어(Skip) 버립니다. 키보드만으로는 위젯을 수정 모드(텍스트 모드)로 되돌릴 수 없는 심각한 접근성 문제가 발생했습니다.

### 근본 원인
CodeMirror 6의 `Decoration.replace({ widget, block: true })` 옵션 때문이었습니다.
`block: true`로 설정된 교체(Replace) 위젯은 CodeMirror 내부적으로 **"접근할 수 없는 단일 블록(Unbreakable Block)"**으로 취급됩니다. 따라서 수직 커서 이동 로직(Arrow Up/Down)이 해당 라인을 텍스트 라인으로 인지하지 못하고 아예 건너뛰게 됩니다.

### 해결 방법
타이틀 바 및 닫는 펜스 위젯의 속성을 인라인 위젯인 **`block: false`**로 변경했습니다.
인라인 위젯으로 삽입되면 CodeMirror는 해당 위젯을 일반 텍스트 라인(`.cm-line`)의 일부로 취급하므로, 방향키 이동 시 건너뛰지 않고 정상적으로 해당 라인에 커서가 안착(Landing)하게 됩니다.

## 2. 마우스 클릭 불가 (` ``` ` 접근 불가) 현상

### 증상
마우스로 타이틀 바 위젯이나 코드 블록 하단의 빈 공간(닫는 펜스 위젯)을 클릭해도 아무런 반응이 일어나지 않으며, 커서가 해당 위치로 이동하지 않아 마크다운 구문을 노출시킬 수 없었습니다.

### 근본 원인
CodeMirror의 **위젯 클릭 매핑(Widget Click Mapping)** 한계 때문입니다.
사용자가 복잡한 DOM 구조(div, span, 버튼 등이 중첩된 구조)를 가진 위젯 내부를 클릭할 때, CodeMirror의 기본 좌표 계산 로직(`posAtCoords`)은 종종 해당 클릭 위치가 에디터 내 텍스트의 어느 위치(`pos`)에 해당하는지 역산해내는 데 실패합니다. 이 계산에 실패하면 CodeMirror는 안전을 위해 해당 마우스 클릭 이벤트를 단순히 무시(Ignore)해 버립니다.

### 해결 방법
CodeMirror의 자동 좌표 매핑에 의존하지 않고, **명시적 클릭 핸들러 (Explicit Click Handler)**를 직접 구현하여 해결했습니다.
1. **위젯에 위치 부여**: `CodeBlockHeaderWidget` 및 `CodeBlockFooterWidget` 생성 시, 자신이 대체한 마크다운 문자의 원래 위치(`pos`)를 인자로 넘겨받습니다.
2. **커스텀 이벤트 발송**: 위젯 DOM 컨테이너에 `mousedown` 이벤트 리스너를 달아, 클릭 시 브라우저 기본 동작을 막고(`e.preventDefault()`) 커스텀 이벤트인 `code-block-click`을 발생시킵니다. 이때 `detail` 객체에 자신의 `pos`를 담아 보냅니다.
3. **커서 순간 이동 (ViewPlugin)**: 에디터 전역에서 `code-block-click` 이벤트를 감시하는 `codeBlockInteractionPlugin`을 작성했습니다. 이벤트가 감지되면 전달받은 `pos` 값을 이용해 명시적인 CodeMirror 트랜잭션(`view.dispatch({ selection: { anchor: pos } })`)을 발생시켜, 커서를 해당 펜스 위치로 순간 이동(Teleport)시킵니다.

## 3. 타이틀 바와 코드 배경 사이의 투명한 갭(Gap) 현상

### 증상
위젯을 `block: true`에서 인라인 위젯(`block: false`)으로 변경하자, 타이틀 바 위젯과 그 아래 실제 코드 블록 배경색 사이에 약 4~6px 가량의 투명한 틈새(Gap)가 발생했습니다.

### 근본 원인
**텍스트 베이스라인(Baseline) 하단 여백 문제**입니다.
인라인 위젯은 필연적으로 텍스트 라인을 감싸는 `.cm-line` 컨테이너 내부에 렌더링됩니다. 이 `.cm-line` 컨테이너는 에디터의 기본 폰트 크기(`font-size`)와 줄 간격(`line-height`) 속성을 그대로 상속받습니다. 
타이틀 바 위젯이 텍스트 베이스라인 위에 얹혀지면서, 베이스라인 아래쪽에 알파벳 'g', 'p', 'y' 같은 글자(Descender)가 뻗어나갈 수 있도록 예약된 미세한 하단 여백이 남게 되고, 이 공간이 갭(Gap)으로 노출된 것입니다.

### 해결 방법
인라인 위젯이 렌더링되는 래퍼 라인에 `.cm-code-block-widget-line`이라는 전용 CSS 클래스를 부여하고, 해당 클래스에 **`fontSize: 0` 및 `lineHeight: 0`** 속성을 강제로 주입했습니다. 
이를 통해 감싸고 있는 텍스트 컨테이너의 높이를 0으로 완전히 압축(Collapse)시켜 베이스라인 여백을 원천적으로 제거하였고, 타이틀 바와 코드 배경이 완벽하게 밀착되도록 만들었습니다. (필요 시 CodeMirror가 자동 주입하는 `<br>` 태그도 `display: none`으로 숨김 처리합니다.)
