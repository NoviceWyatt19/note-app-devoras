## 🗺️ 1. 프로젝트 현재 상황 개요
* **현재 마일스톤:** Devoras 데스크톱 MVP Phase 1 (Tauri 2 + CodeMirror 6 에디터 + Mind View 파싱)
* **진척도:** 60% 완료 (기초 에디터 상태/포커스 안정화 및 런타임 셋업 완료, H1-H2 헤딩 파싱 및 마인드 뷰 노드 좌표 연동 착수 단계)

## ⚖️ 2. 기존 기획 vs 현재 단계 비교

| 기능/도메인 | 기존 기획 (Plan / functions) | 현재 단계 및 확정 스펙 (Actual) |
| :--- | :--- | :--- |
| **헤딩(H) 태그 파싱** | H1~H6 대등한 블록/노드로 수용 | **H1**: 최상위 루트 블록 / **H2**: 실질적 메인 카드 블록 / **H3~H6**: H2 하위 시각화 노드로 역할 명확화 |

## ⚠️ 3. 기획 상의 차이점 및 변경 사유 (Gaps & Discrepancies)

* **이슈 항목 1: H 태그의 역할 및 블록 범위 재정의**
  * **변경 내용**: `H1`은 노트 전체의 최상위 루트 블록으로 관리하며, `H2`를 실질적인 에디터 분할/병합의 메인 단위 블록으로 인정하고, `H3`~`H6`은 에디터 블록이 아닌 마인드 뷰에서의 하위 서브 노드로 인식.
  * **변경 사유**: 블록 분할 과정에서의 포커스/커서 점프 불확실성을 제거하고, 개발자가 아키텍처나 지식을 구성할 때 가장 자연스러운 Markdown 멘탈 모델 제공.
  * **영향도**: 에디터 상태 조작 단순화, 파서 노드 트리 분류 명확화 및 마인드 뷰 렌더링 성능 향상.

* **이슈 항목 2: `functions/` 명세 문서의 순차적 구현 로드맵 수립**
  * **변경 내용**: `functions/` 경로에 정의된 1~9번 기능들을 한 번에 구축하지 않고, 기본 노트 작성 및 마인드 뷰 투영 안정화 후 단계적으로 커스터마이징.
  * **변경 사유**: 단기 MVP의 핵심 가치(메모장 같은 가벼움 + 마인드 뷰 자동 투영)에 집중하기 위해 기능 우선순위 조율.
  * **영향도**: 개발 챗에 명확한 단위 티켓 발급 가능.
