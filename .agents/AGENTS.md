# 프로젝트 규칙 (Project Rules)

## 깃 커밋 및 버전 관리 규칙 (Git Commit and Versioning Rules)

### 1. 커밋 템플릿
커밋 메시지는 항상 다음 템플릿을 준수합니다:
`커밋 속성(현재 버전): 설명`

#### 커밋 속성 정의:
- `feat`: 기능 개발 관련
- `refactor`: 리펙토링 관련
- `style`: 외부 이미지 변경 및 주석 관리
- `chore`: 세팅 및 기능과 관련 없는 자잘한 변경
- `fix`: 에러 해결 및 대응
- `project`: 버전 변경 및 프로젝트 단위의 변경 발생 시 사용 (거의 사용하지 않으며, 누락된 항목을 처리할 때)
- `속성명_add`: 이전 커밋에서 누락된 변경사항을 추가할 때 사용 (예: `feat_add`, `chore_add`)

### 2. 커밋 전 버전업 규칙
모든 커밋을 수행하기 전에 프로젝트 버전을 업데이트해야 합니다:
- 버전은 `x.x.x` 형식을 따릅니다.
- **패치 버전 (3번째 자리 - x.x.X)**: 자잘한 변경 또는 거의 모든 커밋 단위의 변경 시 1씩 증가시킵니다.
- **마이너 버전 (2번째 자리 - x.X.x)**: 신규 기능 추가 또는 대규모 변경 시 증가시킵니다.
- **메이저 버전 (1번째 자리 - X.x.x)**: 프로젝트의 파괴적/거대한 변경 및 중대한 기능/성격 추가 시 사용하며, 보통 사용자의 직접 명령에 의해서만 증가시킵니다.

#### 업데이트 대상 파일:
- `project/package.json`
- `project/src-tauri/Cargo.toml`
- `project/src-tauri/tauri.conf.json`

#### 버전업 예외 (문서 전용 변경)
**문서만 변경한 커밋은 버전을 올리지 않습니다.** 위 업데이트 대상 파일을 건드리지 않고 그대로 둡니다.
- 대상: `.md` 문서(`DEBUG_PLAN.md`, `DEBUG_STEP_PLAN.md`, `code_review.md`, `implementation_plan.md`, `README.md`, `.agents/` 규칙 문서 등), `ticket/` 의 티켓 파일, 문서 아카이브 이동(`claude-history/`).
- 코드·설정 변경이 **한 줄이라도 섞이면** 예외가 아닙니다. 통상대로 패치 버전업을 수행합니다.
- 커밋 속성은 `chore` 또는 `docs` 성격의 `chore` 를 사용하고, 괄호 안에는 **변경 없이 유지된 현재 버전**을 그대로 적습니다.
  ```
  chore(0.8.32): DEBUG_PLAN 갱신 — Step 1~3 사양 수립
  ```
