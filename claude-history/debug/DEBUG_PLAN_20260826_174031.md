## 1. 증거 — 런타임 로그로 확정

`~/Library/Logs/com.devoras.desktop/Devoras.log`:

```
[2026-08-26][08:01:15][tauri::protocol::asset][ERROR] asset protocol not configured to allow the path:
  /Users/wyattkim/Dev/01_inflearn/hong_docker/.devoras/images/img_1786512657264.png
```

이 문자열은 `tauri-2.11.5/src/protocol/asset.rs` 에서 **정확히 한 곳**에서만 출력된다:

```rust
// asset.rs:46-49
if !scope.is_allowed(&path) {
    log::error!("asset protocol not configured to allow the path: {path}");
    return resp.status(403).body(Vec::new().into()).map_err(Into::into);
}
```

### 403 을 낼 수 있는 세 경로 중 어느 것인가

| # | 위치 | 조건 | 판정 |
|---|---|---|---|
| 1 | `asset.rs:41` | `SafePathBuf::new` 실패 = 경로에 `../` 포함 | **해당 없음** — 로그 메시지가 다름 (`is not valid`) |
| 2 | `asset.rs:46` | `scope.is_allowed()` == false | **✅ 확정** — 로그 메시지 일치 |
| 3 | `asset.rs:66` | OS 레벨 `PermissionDenied` | **해당 없음** — 로그 메시지가 다름 (`Missing OS permission`) |

→ **파일은 존재하고(404 아님), OS 권한도 있으며(3번 아님), 순수하게 Tauri scope 매칭에서 거부**되었다.

### 로그의 결정적 특징

로그에 찍힌 실패 경로는 **전부 `.devoras/images/` 하위**다. `assets/images/`, `_assets/` 경로의 실패 기록은 **단 한 건도 없다**. 즉 `"**"` 패턴은 절대 경로를 정상적으로 매칭하고 있으며, **오직 dot 디렉터리에서만** 실패한다.

## 2. 근본 원인 — 코드 레벨 추적

### 2.1 scope 생성부: dot 제약이 주입되는 지점

`tauri-2.11.5/src/scope/fs.rs:215-224` — `Scope::new()`

```rust
let require_literal_leading_dot = match scope {
    FsScope::Scope { require_literal_leading_dot: Some(require), .. } => *require,
    // dotfiles are not supposed to be exposed by default on unix
    #[cfg(unix)]
    _ => true,          // ← 현재 설정이 여기에 해당
    #[cfg(windows)]
    _ => false,
};
```

현재 `tauri.conf.json` 의 scope 는 **문자열 배열**이므로 `FsScope::AllowedPaths` 로 역직렬화된다. 이 variant 에는 `require_literal_leading_dot` 필드 자체가 없어 `_ => true` 분기로 떨어진다. macOS = unix → **`true`**.

`tauri-utils-2.9.3/src/config.rs:2532-2555`:

```rust
#[serde(untagged)]
pub enum FsScope {
    AllowedPaths(Vec<PathBuf>),                       // ← 배열 형태. 옵션 지정 불가
    #[serde(rename_all = "camelCase")]
    Scope { allow: Vec<PathBuf>, deny: Vec<PathBuf>,
            require_literal_leading_dot: Option<bool> },  // ← 객체 형태. 여기서만 제어 가능
}
```

### 2.2 매칭부: `**` 가 dot 컴포넌트에서 끊기는 지점

`glob-0.3.3/src/lib.rs:818-824`:

```rust
while let Some(c) = file.next() {
    if follows_separator && options.require_literal_leading_dot && c == '.' {
        return SubPatternDoesntMatch;      // ← 여기서 즉시 실패
    }
    follows_separator = path::is_separator(c);
    match *token {
        AnyRecursiveSequence if !follows_separator => continue,   // ← `**` 토큰
        ...
```

`AnyRecursiveSequence` = glob 의 `**`. 이 루프는 `**` 가 경로를 탐색하며 전진할 때 **구분자 직후 문자가 `.` 이면 무조건 매칭 실패**시킨다.

### 2.3 결론 — 실패 체인

```
BlockEditor 이미지 붙여넣기
  └ saveImageAssetWithPolicy()                 [src/shared/lib/fs/imageAsset.ts:28]
      imageSavePolicy = 'workspace-root-hidden'  ← 기본 정책
      └ 저장 위치: {workspace}/.devoras/images/{file}     ← dot 디렉터리
      └ 마크다운 삽입 경로: ".devoras/images/{file}"
          └ ReadView.resolveAssetPaths()        [src/widgets/BlockEditor/ui/ReadView.tsx:83]
          └ ImageDecorator.toDOM()              [src/shared/lib/editor/decorators/impl/ImageDecorator.ts:46]
              └ convertFileSrc(absPath)
                  → "asset://localhost/Users/.../.devoras/images/img.png"
                      └ Rust: scope.is_allowed()
                          패턴 "**" vs 경로 ".../.devoras/..."
                          → glob: follows_separator && require_literal_leading_dot && c=='.'
                          → SubPatternDoesntMatch
                              → 403 Forbidden ❌
```

### 2.4 이전 수정(`6c6fab0`)이 실패한 이유

```json
"scope": ["**", "$DESKTOP/**", "$HOME/**", "$DOCUMENT/**"]
```

- 배열 형태를 유지 → `FsScope::AllowedPaths` → `require_literal_leading_dot` 여전히 `true`.
- 추가된 세 패턴 모두 `**` 로 끝남 → §2.2 제약을 **동일하게** 받음.
- 게다가 `"**"` 는 이미 모든 절대 경로를 커버하므로 세 패턴은 **기능적으로 완전 중복**. 아무것도 바뀌지 않았다.

→ **문제는 "어떤 경로를 허용하는가"가 아니라 "매칭 옵션"이었다.** 패턴 목록을 아무리 늘려도 해결되지 않는다.

## 3. 수정 계획

### 3.1 [단독 수정] `project/src-tauri/tauri.conf.json`

**Before**
```json
"assetProtocol": {
  "enable": true,
  "scope": ["**", "$DESKTOP/**", "$HOME/**", "$DOCUMENT/**"]
}
```

**After**
```json
"assetProtocol": {
  "enable": true,
  "scope": {
    "allow": ["**"],
    "deny": [],
    "requireLiteralLeadingDot": false
  }
}
```

**변경 요지 3가지**

1. **배열 → 객체**: `FsScope::Scope` variant 로 역직렬화되어야 옵션 필드를 읽는다. 이게 핵심.
2. **`requireLiteralLeadingDot: false`**: `.devoras/` 를 `**` 가 통과할 수 있게 한다.
3. **중복 패턴 제거**: `$DESKTOP/**`, `$HOME/**`, `$DOCUMENT/**` 는 `"**"` 의 진부분집합이므로 삭제. 스코프 축소가 아니라 **noise 제거**이며 허용 범위는 변하지 않는다.

**스키마 검증**: `node_modules/@tauri-apps/cli/config.schema.json` 의 `FsScope` 정의에 `anyOf: [배열, {allow, deny, requireLiteralLeadingDot}]` 가 존재함을 확인 완료. 객체 형태는 유효한 설정이다.

### 3.2 프론트엔드 — 변경 없음

`ReadView.resolveAssetPaths`, `ImageDecorator.toDOM`, `imageAsset.saveImageAssetWithPolicy` 모두 **정상 동작 중**이다. 로그의 요청 경로가 실제 파일 위치와 정확히 일치하는 것이 그 증거다. 이 파일들은 건드리지 않는다.

### 3.3 함께 정리할 부수 항목 (선택)

| 항목 | 내용 | 우선순위 |
|---|---|---|
| 버전 불일치 | `tauri.conf.json` = `0.8.3`, `package.json`/`Cargo.toml` = `0.8.4` | 낮음 — 이번 수정과 함께 `0.8.5` 로 정렬 |

## 4. 보안 검토

`requireLiteralLeadingDot: false` 는 asset 프로토콜이 **dot 으로 시작하는 경로를 읽을 수 있게** 만든다. 평가:

- **필수 불가결**: 앱의 **기본** 이미지 저장 정책(`workspace-root-hidden`)이 `.devoras/` 를 쓴다. 이 옵션 없이는 기본 정책이 원천적으로 동작 불가.
- **노출 증가분**: 기존 scope 가 이미 `"**"` (전체 파일시스템)이므로, 이번 변경으로 새로 열리는 것은 **dot 파일뿐**이다. 실질 증가분은 `~/.ssh/`, `~/.aws/` 등.
- **잔여 리스크**: `csp: null` 상태에서 마크다운 XSS 가 성립하면 dot 파일 유출 경로가 된다. 이는 아카이브된 계획서의 **P0-1(마크다운 XSS)** 항목과 직접 연결된다. 다만 P0-1 은 `"**"` 만으로도 이미 홈 디렉터리 전체가 노출되는 문제이므로, **이번 변경이 P0-1 의 심각도를 바꾸지는 않는다**.
- **권고 (후속 티켓, 이번 수정 범위 밖)**: `"**"` 를 워크스페이스 루트 기반 동적 scope(`asset_protocol_scope().allow_directory()`)로 좁히고, `deny` 에 `$HOME/.ssh/**`, `$HOME/.aws/**`, `$HOME/.config/**` 를 추가. 이는 별도 작업으로 분리한다.

## 5. 검증 절차 (DoD)

### 5.1 빌드 — **반드시 Rust 재빌드**

`tauri.conf.json` 은 `tauri::generate_context!()` 매크로를 통해 **컴파일 타임에 바이너리에 인라인**된다. Vite HMR 이나 프론트엔드 재시작으로는 절대 반영되지 않는다.

```bash
cd project && pnpm tauri dev
```

```bash
cd project/src-tauri && touch build.rs && cd .. && pnpm tauri dev
```

### 5.3 실패 시 다음 가설 (V1 이 여전히 실패할 경우에만)

1. **재빌드가 실제로 안 된 경우** — 가장 흔함. `src-tauri/target/` 삭제 후 재빌드.
2. **404 로 코드가 바뀐 경우** — scope 는 뚫렸으나 파일이 실제로 없음. `ls` 로 물리적 존재 확인.
3. **심볼릭 링크 경로** — `is_allowed()` 는 `try_resolve_symlink_and_canonicalize()` 로 정규화 후 매칭한다. 워크스페이스가 심링크 경유 경로면 canonical 경로 기준으로 재확인.
4. **`window_origin` / CORS** — 403 이 아닌 CORS 에러로 증상이 바뀌었다면 별개 이슈로 분리.
