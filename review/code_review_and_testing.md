# Devoras v0.1.1 테스트 계획 및 v1.0.0 코드 리뷰 보고서

이 보고서는 현재 안정화된 `v0.1.1` 기능의 오동작을 방지하기 위해 수행해야 하는 **테스트 시나리오 목록**과, 차기 릴리즈인 `v1.0.0`으로 전환하기 전에 반드시 선결해야 하는 **코드 리팩터링 포인트 및 개선 계획**을 정리한 문서입니다.

---

## 1. v0.1.1 기능 보장을 위한 테스트 시나리오 목록

핵심 기능의 투영 안정성을 확보하기 위해 다음 항목들을 대상으로 수동 및 단위 테스트를 수행해야 합니다.

### A. 파일 입출력 및 워크스페이스 테스트
1. **폴더 마운팅 및 새로고침**:
   - 빈 폴더 및 다수의 마크다운 파일이 포함된 로컬 폴더를 열었을 때 파일 목록이 정확히 로드되는지 확인.
   - 외부에서 폴더 내 파일 변경 후 탐색기 '새로고침' 시 목록이 동기화되는지 검증.
2. **새 파일 생성 및 로드**:
   - 새 마크다운 파일 생성 시 뼈대 텍스트(예: H1 제목 + 초기 문장)가 자동 저장되는지 확인.
   - 생성 즉시 파일 탐색기 목록이 갱신되고, 에디터와 마인드 뷰가 즉시 포커스되어 열리는지 검증.
3. **저장 상태 및 단축키 검증**:
   - 편집 시 파일명 우측에 `dirty(노란 점)` 표시가 활성화되는지 확인.
   - `Cmd+S` (macOS) / `Ctrl+S` (Windows) 단축키 입력 시 dirty 마커가 즉시 사라지고 실제 파일로 저장되는지 확인.

### B. Seamless 블록 에디터 조작성 테스트
1. **블록 분할 (Split - Enter)**:
   - 문단 중간에서 `Enter` 입력 시 커서 뒷부분이 신규 블록으로 쪼개져 아래에 생성되고, 커서가 신규 블록의 맨 앞으로 무사히 포커스 이동하는지 확인.
2. **블록 병합 (Merge - Backspace)**:
   - 블록의 맨 첫 번째 인덱(커서 offset 0)에서 `Backspace` 입력 시 현재 블록의 내용이 이전 블록의 끝에 결합되고, 기존 블록은 제거되며, 결합 시점 위치로 커서가 이동하는지 검증.
3. **크로스 블록 방향키 이동**:
   - 블록의 첫 줄에서 `ArrowUp` 입력 시 이전 블록의 마지막 위치로 커서 포커스가 자연스럽게 전이되는지 확인.
   - 블록의 마지막 줄에서 `ArrowDown` 입력 시 다음 블록의 첫 번째 위치로 전이되는지 확인.

### C. 단방향 투영 및 드래그 보존 테스트
1. **실시간 마인드 맵 렌더링**:
   - 에디터에서 헤더 `#`, `##` 등을 추가/제거/수정할 때 우측 마인드맵 노드가 1:1로 실시간 추가/제거되는지 확인.
   - 비정상 헤더 구조(예: H1 없이 H3가 바로 오는 구조)가 입력되더라도 앱이 중단되지 않고 계층 선이 정상 렌더링되는지 확인.
2. **노드 드래그 좌표 영속성**:
   - 마인드 뷰에서 임의의 노드를 드래그하여 좌표를 이동시킨 후, 문서를 저장(`Cmd+S`)하고 다시 열었을 때 지정했던 노드 위치가 완벽하게 복원되는지 확인.
   - 드래그된 노드의 좌표 정보가 마크다운 텍스트 원문 최하단에 `<!-- devoras:spatial ... -->` 주석 형태로 정상 인코딩되어 삽입되는지 파일 원문 검사.

## 2. v1.0.0 전환을 위한 코드 리뷰 및 리팩터링 방향

현재 소스 코드 분석 결과, 로드맵의 **v1.0.0 ERD DSL 기능 추가 및 고도화** 시점에 심각한 장애를 유발할 수 있는 잠재적 결함 포인트들을 식별하였습니다.

### 🔍 [Point 1] 코드 블록 격리 부재 (Parser 취약점)
- **위치**: [parser.ts](file:///Users/wyattkim/Desktop/Devoras-Design/project/src/entities/document/lib/parser.ts#L43-L45)
- **현상**: 현재 마크다운 파싱 시 정규식(`^(#{1,6})\s+(.+)$`)을 파일 전체 라인에 단순 매핑하고 있습니다. 이로 인해 소스 코드 블록(예: ` ```rust ` 내부에 주석으로 작성된 `# 헤딩` 등) 내의 텍스트마저 헤더 노드로 오인하여 마인드맵에 투영하는 취약점이 있습니다.
- **v1.0.0 리팩터링 방안**: 파싱 전 마크다운 코드 블록 영역(```)을 스캔하여 파싱 대상에서 제외(Muting/격리)하는 정밀한 전처리 파서 로직을 추가해야 합니다.

### 🔍 [Point 2] 단순 줄바꿈 분할 한계 (Editor 취약점)
- **위치**: [store.ts](file:///Users/wyattkim/Desktop/Devoras-Design/project/src/entities/block/model/store.ts#L22-L24)
- **현상**: 현재 문서를 블록으로 쪼갤 때 단순 개행 `split('\n\n')`을 사용합니다. 만약 마크다운 내부에 표(Table), 리스트, 혹은 소스 코드 블록이 있고 그 안에 빈 줄이 존재할 경우, 하나의 코드 블록이 강제로 여러 조각의 에디터 블록으로 조각나 깨지는 결함이 발생합니다.
- **v1.0.0 리팩터링 방안**: AST 파싱 구조를 활용하거나, 코드 블록 및 테이블 영역이 온전히 하나의 `EditorBlock`으로 묶이도록 개선된 분할 정규식 또는 상태 기반 스캐너 로직을 도입해야 합니다.

### 🔍 [Point 3] 순서 변경 시 좌표 뒤틀림 이슈
- **위치**: [parser.ts](file:///Users/wyattkim/Desktop/Devoras-Design/project/src/entities/document/lib/parser.ts#L65-L67)
- **현상**: 동일 제목을 가진 노드 구분을 위해 `siblingCountMap`을 사용하여 `_2`, `_3` 등의 접미사를 붙이고 있습니다. 그러나 사용자가 텍스트 편집 중에 첫 번째 중복 노드를 삭제하게 되면, 두 번째 중복 노드의 ID가 `_2`에서 접미사가 없는 기본 ID로 당겨지게 됩니다. 이로 인해 기존에 `_2` 키값으로 저장되어 있던 노드 위치 데이터와 어긋나 노드 좌표가 원래 자리로 순간 이동하는 현상이 유발될 수 있습니다.
- **v1.0.0 리팩터링 방안**: 헤딩 텍스트 옆에 보이지 않는 고유 키 인라인 주석(예: `# 제목 <!-- id: unique-key -->`)을 파서 수준에서 매칭하거나, 형제 순서가 바뀌어도 좌표 유실을 최소화하는 안정적 매칭 알고리즘 고도화가 요구됩니다.

### 🔍 [Point 4] CodeMirror 렌더링 최적화
- **위치**: [BlockEditor.tsx](file:///Users/wyattkim/Desktop/Devoras-Design/project/src/widgets/BlockEditor/ui/BlockEditor.tsx#L143-L145)
- **현상**: 여러 개의 CodeMirror 6 에디터 컴포넌트가 존재할 때, 하나의 블록에서 타이핑이 일어날 때마다 전체 `BlockEditor` 컴포넌트가 동시 리렌더링되어 타이핑 수가 늘어날 때 랙이 유발될 수 있습니다.
- **v1.0.0 리팩터링 방안**: 각 에디터 블록 컴포넌트를 `React.memo`로 감싸고, Zustand 셀렉터 최적화를 적용하여 현재 편집 중인 블록만 국소적으로 리렌더링되도록 최적화해야 합니다.
